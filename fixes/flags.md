# Флаг в A/D: где живёт и как не отдать его атакующим

Это главный файл: в A/D победа = чужие флаги + свои не отданы. Любая уязвимость
интересна ровно потому, что ведёт к flag store. Сначала находим, где флаг,
потом закрываем каналы.

## Где обычно лежит флаг

| Место | Пример | Как проверить |
|---|---|---|
| БД | таблица/коллекция `flags`, поле в `users` | `SELECT * FROM flags`, `db.flags.find()` |
| Файл | `/flag`, `/app/flag.txt`, `/tmp/flag` | `find / -name '*flag*' -readable` |
| ENV | `FLAG=...` | `env | grep -i flag`, `docker inspect` |
| Память | флаг в кэше/шаблоне ответа | `strings /proc/<pid>/mem`, дамп переменной |
| Внешний сервис | чекер-API, флаг-стор по HTTP | `ss -tlnp`, конфиги |

В большинстве сервисов флаг кладётся чекером в БД/файл на каждый тик, а сервис
должен отдавать его только «своим» (по токену/сессии). Значит, дыра — это
обычно **доступ к чужому флагу**, а не RCE.

## Каналы утечки — чеклист на каждый сервис

1. **Публичный эндпоинт без авторизации**: `/flag`, `/flags`, `/admin`,
   `/api/v1/flag`, GraphQL-запросы, отладочные роуты.
2. **IDOR**: `/flag/1`, `/user/2/flag`, `?team=3` — предсказуемые ID, нет
   проверки владельца.
3. **Инъекции**: SQLi/NoSQLi/SSTI/LFI/CMDi — читают БД/файл/окружение.
4. **Ошибки и отладка**: стектрейсы, `/debug`, `/metrics`, `/status`, дампы
   конфигов, `phpinfo`, `/actuator/env`.
5. **Логи наружу**: `/logs`, `/admin/log`, ошибки с данными запроса.
6. **Исходники и бэкапы**: `.git/`, `.env`, `*.bak`, `*.sql`, `backup.zip` —
   там пароли/секреты/пути к флагу.
7. **Слабые креды**: дефолтный админ, пароль из репо, пустой токен.
8. **SSRF**: сервис сам ходит во внутренний flag store/метаданные.
9. **Гонки**: флаг выдан дважды, не удалён после выдачи, чужой тик.
10. **Побочные каналы**: время ответа, разница ошибок, размер ответа.

## Как закрыть, не сломав чекер

- Чекер ходит **своим** путём (обычно кладёт/читает флаг по токену команды).
  Не трогай этот контракт: не меняй формат, метод, коды ответа.
- Эндпоинт выдачи флага: строгая аутентификация + проверка владельца:
  ```python
  flag = db.get_flag(flag_id)
  if not flag or flag.owner_id != session["user_id"]:
      abort(404)            # 404, не 403 — не подтверждай существование
  ```
- Ошибки наружу — один общий ответ, без деталей:
  ```python
  @app.errorhandler(Exception)
  def on_error(e):
      log.exception("request failed")       # локально, без флагов в логе
      return "internal error", 500
  ```
- Отключить debug: `FLASK_DEBUG=0`, `DEBUG=False`, `display_errors=Off`,
  `NODE_ENV=production`, убрать `/debug`/`/test` роуты.
- Закрыть статику (nginx/Firegex):
  ```nginx
  location ~ /\.(git|env|svn|hg) { deny all; }
  location ~* \.(bak|old|orig|swp|sql|tar\.gz|zip)$ { deny all; }
  ```
- Не логировать флаги/токены/пароли: маскируй перед логом.
- IDOR: любые выборки по id из запроса — с условием владельца, а не
  `get(id)`.

## Проверка после патча

```bash
# 1. старые PoC должны перестать работать
curl -si http://SVC/flag                      # 401/404
curl -si http://SVC/flag/1 -H "Cookie: ..."   # 404/403 для чужого
curl -si http://SVC/.git/config               # 403/404
curl -si http://SVC/debug                     # 404
# 2. чекер-путь должен работать (симулятор/борда)
# 3. watch_status: UP стабильно 1-2 тика
```

## Что нельзя

- Менять формат флага/API, которым ходит чекер.
- Блокировать чекер целиком «на всякий случай» — это MUMBLE.
- Удалять флаг из БД после выдачи, если чекер перечитывает его повторно.
- Прятать флаг в другое место, которое сервис всё равно отдаёт наружу.
